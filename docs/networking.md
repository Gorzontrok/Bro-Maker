# 自定义角色联机接入说明

本说明对应当前开发分支配套 RocketLib 的公共接入，既有 `Release` 包不代表已包含这些源码改动。各参与端需要安装配套框架及相同的角色模组与资源。

2026-11-07 起，本轮主线交付聚焦公共框架；不再逐个迁移、补测其他消费者。已有 Aquabro、Drunken 改动和有限验证保留，后续角色适配由作者完成。

## 框架已经处理的部分

| 路径 | 当前处理 |
| --- | --- |
| 正常 BroMaker 角色加载 | `BroMaker:hero:<name>` 稳定 ID，名称、player slot 和拥有端 variant 随生成传递 |
| 模组与 prefab 清单 | 发布 BroMaker 版本、角色所属模组版本及组件信息，按参与端清单过滤可用角色 |
| 自定义 projectile/grenade/sachel 的 `CreatePrefab` | 在新建和缓存路径登记 `BroMaker:<Type.Name>`，由 RocketLib 公共网络路径解析与生成 |
| `CustomHero.Start` | 正常执行基类后，在线本人且满足 `MustSync()` 时启用同步，支持出生未移动时的输入 |
| 普通 fire | 在 RocketLib 协商条件成立且角色使用公共 Update/CheckInput 路径时，复用其输入记录和时间执行 |

角色名必须唯一。自定义投射物的简单类型名也不能冲突；相同 `Type.Name` 即使位于不同 namespace 仍有歧义。缺角色、版本不符或组件信息不完整时，不应靠伪造 NID 或强行放行绕过框架。

## 最小接入步骤

1. 通过正常 BroMaker 角色定义和加载路径使用 `CustomHero` 或对应受支持接口，保留必要的基类生命周期调用。沿正常网络选角流程生成角色，镜像不再手动加载第二份角色。
2. 使用 `CustomProjectile`、`CustomGrenade`、`CustomSachelPack` 的框架 `CreatePrefab` 路径创建自定义 prefab。若直接复制 GameObject 或绕过该路径，作者须自行补齐注册，不能假定自动识别。
3. 将需要共享的本地生成改为匹配的游戏网络生成入口，并仅由约定拥有端发起。对普通自定义 `Projectile`，角色内部可沿以下路径调用：

```csharp
if (Connect.IsOffline || IsMine)
{
    ProjectileController.SpawnProjectileOverNetwork(
        prefab, this, X, Y, xI, yI, false, playerNum, false, false, 0f);
}
```

这里 `prefab` 是已按框架创建的 projectile，`xI/yI` 是该动作确定的速度。grenade 和其他对象使用其自身匹配的生成接口与参数。镜像继续原生动画和表现，不因也进入攻击回调而再发一次网络生成；离线保留原有动作规则。

4. 正常 prefab 清单和生成已由框架接入，不另写 `InstantiateRPC` 或复制 RocketLib 注册系统。若修改组件结构或添加自定义参数，确保双方 resolver 可构建相同结构，并同步更新模组兼容版本。

## 仍由角色作者适配的部分

| 机制 | 需要作者明确 |
| --- | --- |
| 随机物品或随机技能 | 拥有端决定一次结果，镜像应用该结果，不能双方各自抽取 |
| 技能选择、次数与持物状态 | 状态的权威来源、应用时机、成功和取消，以及必要的状态传递 |
| 自定义伤害、爆炸和持续区域 | 实际命中和最终结算端，重复回调或双端副本不能造成重复伤害 |
| 角色专属事件 | 能力版本、动作身份、真实发送者、重复/过期/乱序边界 |
| 死亡、换角、退场与重生 | 释放临时状态，拒绝旧完整 NID/owner/实例的事件 |

这些可以复用 `RocketLib.Network.ModNegotiation` 和游戏已有 RPC。不要把公共 fire 边沿水位当作技能或投掷事件号，也不要复制某个消费者的专属取物协议当成通用接口。

公共 fire 不保证每 press 一发、精确持键时长或所有角色自定义输入都可捕获。收到同一个 projectile 副本，也不等于共享伤害已通过。完全覆盖 Update 且不走公共基类调用点的角色，需要先核实际输入路径。

## 最小验证范围

- 房主与加入端各作为拥有端，正常选角与执行动作，核对双方类型、完整 NID/owner、槽位及实际组件。
- 确认一次拥有端生成对应双方同一网络对象，镜像没有重复发起；还要看实际初始化与运动。
- 对自己的随机、技能或伤害机制，分别观察结果、次数和共享目标状态；动画或零回调不能代替结算证据。
- 检查重复事件及死亡/换角后的旧事件拒收，再确认正常退房和临时状态清理；离线行为另按受影响范围验证。

已有消费者只证明公共路径可复用。本轮没有认证所有角色、完整技能/伤害、Boss、异图或三端迁移；这些边界不要求本仓库继续逐个改造第三方角色。
